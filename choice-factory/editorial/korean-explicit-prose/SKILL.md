# 명확한 한국어 설명문

독자가 저자의 표현을 해독하지 않고도 무엇을 묻고 무엇을 설명하는 글인지 알게 한다. 문장을 짧게 만드는 것만으로 교정을 끝내지 말고, 제목·도입·본문의 설명 순서가 같은 질문에 답하는지 확인한다.

## 사용자가 보여준 편집 기준

원래 제목: “결심은 바뀌었는데 손은 왜 같은 곳으로 갈까”

사용자 수정: “행동을 수정하겠다고 마음먹은 뒤에도 손은 왜 습관대로 움직이는가”

원래 도입: “바꾸겠다고 생각한 뒤에도 남는 행동이 있다. 의지의 크기를 따지기 전에, 그 행동이 시작되는 자리를 살펴본다.”

사용자 수정: “마음을 고쳐먹은 뒤에도 습관은 쉽게 수정되지 않았다. 의지가 부족해서일까? 습관이 행동을 규제하는 원리를 살펴본다.”

이 예시에서 배울 것은 ‘수정’, ‘규제’ 같은 특정 단어를 반복하는 규칙이 아니다. 무엇을 바꾸려 했는지, 어떤 행동이 남았는지, 어떤 원리를 설명할지 밝힌 판단을 따른다.

## 집필과 교정

- 제목에는 대상 현상과 핵심 질문을 드러낸다. ‘그곳’, ‘남는 것’, ‘자리’, ‘길’ 등이 가리키는 대상이 불분명하면 실제 행동·판단·정보로 구체화한다. 이미 뜻이 분명한 제목은 억지로 질문형으로 바꾸지 않는다.
- 도입에서 관찰된 문제와 독자의 의문을 제시하고, 글이 설명할 원리를 예고한다. 사례로 시작해도 좋지만 핵심 개념을 알아내기 위해 여러 절을 기다리게 하지 않는다.
- ‘손이 같은 곳으로 간다’ 같은 표현 뒤에는 필요에 따라 ‘익숙한 상황에서 이전 행동을 반복한다’처럼 실제 뜻을 밝힌다. 독자가 이해할 수 있는 구체적 장면과 유용한 비유는 살린다.
- 주어·대상·인과관계를 분명히 쓴다. ‘이 차이가 질문을 바꾼다’보다 누가 무엇을 새로 확인해야 하는지 설명한다. ‘역설’, ‘묘한 장면’, ‘불편한 질문’처럼 평가만 붙인 문장은 실제 문제를 서술하도록 고친다.
- 핵심 설명을 먼저 제시한 뒤 연구·사례·응용으로 연결한다. 다만 모든 글을 같은 구성이나 문단 수로 강제하지 않는다. 결론은 본문에서 설명한 판단을 구체적으로 되짚는다.
- 자연스러운 한국어와 지적 밀도를 유지한다. 단순 요약, 실용 팁 나열, 불필요한 학술 용어, 독자를 가르치려는 훈계로 바꾸지 않는다.

## 뜻과 근거 보존

- 문체 교정이 연구의 결론을 강화하지 않게 한다. 가능성·상관·표본 범위·가상 사례를 확정적인 원리나 보편적 인과관계로 바꾸지 않는다.
- 연구 수치·조건·분모·서지·출처 링크·인용문은 유지한다. 실제 주장 변경이 필요하면 문체 수정과 구분하고 근거를 별도로 확인한다.
- 원서 소개, 직접 확인한 연구, 종설·후속 검증, 필자의 해석을 구별한다. 근거 없는 뇌 작동 설명이나 전문 용어를 덧붙이지 않는다.
- 사용자가 직접 쓴 문구는 우선 반영한다. 띄어쓰기·문장부호는 뜻을 바꾸지 않는 범위에서 고칠 수 있다. 예시 하나에서 사용자가 말하지 않은 전면적인 문체 금지 규칙을 만들지 않는다.

## 기존 글을 고칠 때

해당 글 전체를 검토하되 명료한 문장까지 변경 실적을 위해 다시 쓰지 않는다. 제목·도입만 바꿨다면 본문 전체 교정 완료라고 보고하지 않는다. 변경 전후와 유지한 근거의 범위를 남긴다.

웹 문서는 원고와 공개 본문·목차·연결 제목을 일치시킨다. 기존 문단 ID, 저장 키, 삽화 원본과 승인 상태를 보존한다. 본문을 바꾸면 저장된 인용문이 달라진 위치를 가리킬 수 있으므로, 원문 인용을 확인해 표시하거나 기존 메모를 남기고 해당 문단으로 이동시킨다. 엉뚱한 문장에 형광펜을 붙이지 않는다.

스킬 적용은 게시·전송·범위 확대의 새로운 권한을 만들지 않는다. 현재 요청과 프로젝트 지침에 따라 수정과 배포 범위를 결정한다.
